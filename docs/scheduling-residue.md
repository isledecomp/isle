# Scheduling residue of the open rows

Generated by `tools/schedmap.py --all`. No build required. Both bodies are
read from the LINKED images and aligned at **EXACT** level: registers and
frame displacements are kept -- they already match on the population this
screen exists for, so keeping them makes the alignment precise -- and only
relocations are masked (direct branch targets, image-range values), because
our image is laid out at different addresses than retail's.

## The population

This is the third screen. `slotmap.py` sorts rows by frame layout,
`regmap.py` by register assignment; what is left on a row where **both**
already match retail is scheduling. That is the **SLOT-CLEAN + IDENTITY**
cell -- 12 rows -- and nobody had screened it.

## The distinction that matters

| verdict | meaning |
|---|---|
| INTRA-BLOCK | every moved instruction stays inside its own basic block: the instruction scheduler reordering independent operations. The standing verdict that this is not a text target holds. |
| CROSS-BLOCK | a moved instruction changes basic block, i.e. it is emitted amid a different part of the program. This is the class a source statement order could reach. |
| CMPDIR | every unmatched pair is a comparison with transposed operands -- the sealed allocator class, not scheduling. |
| DIFFERENT | an instruction on one side has no counterpart; route to another screen. |
| AMBIGUOUS | too little of the body aligns to judge. |

## What the three INTRA-BLOCK rows are

Each is a single-digit reordering inside one block, which is the
scheduler:

- **`0x100ba7f0` MxDisplaySurface::Create** — 1 instruction(s) reordered inside their own block
  - `inc eax` block 21, moved -1 positions
- **`0x100334b0` Act1State::Act1State** — 2 instruction(s) reordered inside their own block
  - `mov dword ptr [esi + 8], <a>` block 0, moved +4 positions
  - `mov dword ptr [esi + 0x14], 0xffffffff` block 0, moved +4 positions
- **`0x100c6fa0` MxDSBuffer::FUN_100c6fa0** — 1 instruction(s) reordered inside their own block
  - `mov eax, dword ptr [esp + 0xc]` block 19, moved -1 positions

## The one row with cross-block moves, and why it is not source-reachable

`0x1002de10 LegoPathActor::SetTransformAndDestinationFromPoints` is the
only row in the whole open set carrying cross-block moves. Its diff is
clean and reads like a source idiom:

```
  OURS    je  <t>            blk 12      RETAIL  jne <t>        blk 12
          mov eax, -1        blk 13              ...success tail...
          jmp <t>            blk 13              jmp <t>        blk 14
                                                 mov eax, -1    blk 15
```

Retail inverts the guard and places the failure tail at the END of the
function; we emit it inline right after the test. The source is
`if (SetSpline(...) != SUCCESS) { MxTrace(...); return FAILURE; }`, so the
obvious hypothesis is the positive form with the failure in an `else`.
**Tested, and refuted:**

```
  baseline (guard, != SUCCESS)      len 746  nd 154  SHAPE 98.56
  positive if / failure in else     len 696  nd 617  SHAPE 85.43
  positive if, AddActor after       len 696  nd 617  SHAPE 85.43
  guard with == FAILURE             len 747  nd 153  SHAPE 98.56
```

The `else` forms lose 50 bytes because MSVC merges the tails; `== FAILURE`
is a wash. Baseline is the best form. **Cold-tail placement is MSVC's own
block layout, not a source order** -- which retires the CROSS-BLOCK class
on the only row that exhibited it.

## Regression pair

Both reproduce a hand reading:

- `0x100ba7f0 MxDisplaySurface::Create` — INTRA-BLOCK, **exactly one**
  instruction moved, matching the coordinator's hand read of "its entire
  residue is exactly one instruction moved". Measured, that instruction is
  `inc eax` moving one position (ours +500, retail +489) inside block 21;
  the ledger carries no entry for this row, so the specific instruction
  named in the brief could not be cross-checked.
- `0x100c6fa0 MxDSBuffer::FUN_100c6fa0` — INTRA-BLOCK, `mov eax,[esp+0xc]`
  moved one position at equal length (85 vs 85 instructions), which is
  exactly the "clean two-instruction transposition at equal length" on
  record.
