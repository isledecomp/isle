## Why the extension matters

`residue2.py` skips any row where `len(ours) != len(retail)`. That drops
**48 of the 95** open oracled rows. For those rows the decisive question is
not the byte count but whether the extra length is *real code* or only
*encoding*:

* **identical instruction multiset, different byte count → ENCODING.** No
  statement was added or removed. A register choice changed the ModRM cost —
  `[ebp]` with no displacement costs one byte more than `[ebx]`. This is a
  **colouring** problem wearing a length defect's clothes.
* **different instruction multiset → REAL.** Instructions were added or
  removed: a text or inlining problem.

**7 of the 48 length-defect rows are encoding-only**, so they belong in the
colour channel and not, as their length delta suggests, in the text channel.
