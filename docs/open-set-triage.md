# Open-set triage by residue class

Generated by `scratchpad/stl/triage2.py` + `bestof.py` against the current
build (`isle-build-tr03`, LEGO1 **4839/4933**) and `bench/oracles-v2.json`.
It reuses `bench/residue2.py`'s classifier verbatim and extends it two ways.

## Extension 1 — the length-defect rows

`residue2.py` skips any row where `len(ours) != len(retail)`, which drops
**48 of the 95** open oracled rows. For those the decisive question is not
the byte count but whether the extra length is *real code* or only
*encoding*:

* **identical instruction multiset, different byte count -> ENCODING.** No
  statement was added or removed; a register choice changed the ModRM cost
  (`[ebp]` with no displacement costs one byte more than `[ebx]`). A
  colouring problem wearing a length defect's clothes.
* **different instruction multiset -> REAL.** Instructions were added or
  removed: a text or inlining problem.

## Extension 2 — classify from the BEST state, not the default compile

This corrects a defect in the first version of this document. Classifying
from the built object asks "what is wrong in the default compile", but the
useful question is "what is wrong in the best state anyone has reached".
Those differ: **27 rows have a length defect in the default compile yet DO
reach retail's exact length under some carrier state.** They are not text
defects, and the first version of this file filed every one of them as one.
